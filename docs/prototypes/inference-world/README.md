# Euboulia Loop 工作台 · v0.5

从任意一种迭代任务出发，观察方案如何演进，与 Agent 讨论，在新的分支或下一轮应用想法。默认入口无需登录，不要求绑定源码目录。

开发基线：`molou/loop-workbench`；本次特性：`molou/loop-evolution-ui`。英文 PR 指向新基线，原 `molou/inference-world-design` 和 PR #27 不变。

[产品模型与参考](../../loop-workbench.md) · [浏览器验收](loop-qa.md)

## 打开

```sh
python3 -m http.server 8773 --bind 127.0.0.1 --directory docs
```

访问 [本地预览](http://127.0.0.1:8773/prototypes/inference-world/)。也可以通过 `uv run euboulia lab serve` 提供相同静态页面。原型无构建依赖，不调用 Lab 登录 API。

## 体验路线

1. 打开“让知识库回答更可靠”样例：演进图保留基线、已采纳路径、评分更高却未满足引用条件的失败路径，以及待验证的子节点。
2. 选中图上任意节点，主区和右侧讨论同步切换。可以缩放、适应画布、强调当前路径；趋势图保留失败结果，按相同条件和来源类型展示。
3. 在“计划讨论”选择一个未验证方案，提出具体质疑、补充答辩，再“选择验证”。修改计划会保留旧讨论，并重新进入质疑阶段。
4. 在“缩短数据处理耗时”样例选中“减少重复读取”，开始演示运行。暂停后仍可在讨论区选择“调整下一轮”，发送一条新指令，点击“下一轮应用”，再恢复运行。
5. 新节点出现后，从“查看应用节点”查看其产物与执行快照；第一轮计划不会被改写。也可在运行期间与其他角色讨论，或把新想法直接变成分支。
6. 演示达到轮次/时间预算或必要条件失败时返回。刷新后保留中断记录，不自动重放。对抗模式的新一轮计划需要重新质疑、答辩和选择。
7. 从“结果”比较节点，记录采纳/不采纳的依据；从产物沉淀经验，记录适用范围和反例。资料可以保留原文、版本及相关性，再成为新分支的线索。
8. 返回“我的工作台”，新建文档、设计或自定义 Loop。支持数值、0–100 评分、通过/失败/待判断检查项；“必须满足”的标准不能由其他高分抵消。角色名称与后续约定可编辑。

## 录入自己的结果

节点“录入结果”支持手动填写或从 JSON 填入表单；先检查，再保存。例：

```json
{
  "values": { "latency": 92, "correct": "pass" },
  "artifact": "/path/to/report.json 或产物正文",
  "summary": "同一输入数据、相同环境下计时三次，输出逐项对照。"
}
```

`values` 的键与当前评价标准标识一致。数值应为有限数字，评分在 0–100 内，检查项使用 `pass` / `fail` / `unknown`。如包含 `snapshot`，其条件必须与当前节点一致。JSON 最大 256 KB；路径只是引用，不会自动读取。结果标为“用户录入 · 未核验”。

## 保存与版本

- v0.5 使用 `euboulia.loop-workbench.v1`，保存节点、讨论、每节点草稿、表单草稿、执行快照、资料与经验。
- 导出按钮提供完整 JSON 预览、下载链接和复制入口。导入先验证结构与数量，确认后替换当前数据；不影响旧版存储。
- 检测到另一标签页写入时停止本页保存；存储损坏时保留原始数据，提供备份导出。不可读数据可在导出后通过明确的备份恢复替换。
- `research.html` 保留 v0.4 本地研究工作台，见 [原说明](research-readme.md)；`team.html` 保留 v0.3 研究室及连接功能。
- 外观沿用雾白、石墨、奶油黄、暖绿四套模式。手机端从浮动讨论按钮展开完整对话区。

## 交互原型边界

演示 Agent 会结合当前节点和明确的讨论方式给出规则回应；“调整下一轮”和“另开分支”会真实改变原型中的后续计划。尚未调用语言模型、执行源码、读取任意目录或自动检索网页。多角色是流程与权限分工的交互表达，并非已启动多个真实 Agent。

角色对抗参考 AMMO 的提出、质疑、答辩与选择；验收单独判断必要条件。这里未实现 AMMO 的完整运行时、真实独立审计、Git worktree 隔离或任意流程编辑器。
